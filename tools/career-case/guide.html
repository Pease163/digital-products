Работа и приватность

Выберите одну задачу из собственного опыта. Подойдут работа, личный или учебный проект. Обозначьте контекст, свою часть ответственности, технический выбор, наблюдаемый результат, подтверждение и то, что пока нельзя утверждать.

Пустая форма не содержит достижений. Вымышленный пример открывается отдельно и не заменяет ваш черновик. Экспорт примера всегда содержит явную пометку о вымышленном содержании.

  • Редактор хранит один черновик в localStorage этого браузера. Он не отправляет введённый текст, ссылку или файлы в API, не подключает аналитику и не требует аккаунта.
  • Открытие редактора и обычные переходы по ссылкам используют сеть. Сайты назначения и сервис размещения могут вести собственные технические журналы. Сам редактор не открывает введённую ссылку автоматически.
  • В приватном режиме или при запрете хранения автосохранение может не работать. Появится предупреждение. Скачайте JSON-копию до закрытия страницы; очищение браузерных данных удаляет локальный черновик.
  • JSON — личная резервная копия одного кейса. «Открыть резервную копию» принимает только формат этого бесплатного редактора, до 256 КиБ. Старый черновик скачивается перед заменой; в браузере также сохраняется одна копия перед последней заменой, если локальное хранение доступно.
  • Если сохранённые данные повреждены, редактор защищает их от перезаписи. Можно скачать исходник, открыть корректную резервную копию или подтвердить новый пустой кейс.
  • RU/EN переключает подписи и язык экспорта. Ваш текст автоматически не переводится.

Проверьте содержание перед отправкой

Заполненные поля не доказывают достоверность опыта. Не присваивайте результат всей команды. Не вставляйте придуманные проценты, имена клиентов, секреты, внутренние адреса или чужие персональные данные. Если подтверждение закрыто, опишите доступную границу проверки и не публикуйте файл без разрешения.

Ссылка необязательна. Поддерживается HTTPS без логина и пароля в адресе. Редактор проверяет формат, но не существование страницы или доступ получателя. Проверьте её самостоятельно без авторизации. Добровольная ссылка Kornilov Tools в экспорте выключена по умолчанию.

Форматы результата

  • technical-case.md — Markdown для README, заметки или отправки. Он содержит только ваш кейс, без редактора.
  • index.html — самостоятельная страница с встроенными стилями. У неё нет скриптов, шрифтов, изображений и иных внешних ресурсов. Она работает локально без сети; внешняя ссылка открывается только по нажатию.
  • my-case-backup.json — черновик для дальнейшего редактирования. Храните отдельно от публикуемой страницы.
  • one-case-career-library.json — отдельный файл опыта для выбранного импорта в Portfolio Case Kit или Interview Proof Kit. Он сохраняет все поля кейса, его идентификатор и пометку о вымысле; личные настройки редактора в него не входят.

Продолжить в Portfolio или Interview

  1. Заполните обязательные поля и нажмите «Скачать опыт для Portfolio / Interview». Не путайте этот файл с резервной копией редактора.
  2. Откройте свой редактор Portfolio Case Kit или Interview Proof Kit версии 1.1. Выберите «Добавить опыт» и скачанный one-case-career-library.json. Если такой кнопки нет, нужна версия редактора с поддержкой библиотеки опыта.
  3. Проверьте перенесённый кейс. Повторный импорт обновляет тот же идентификатор вместо создания копии. Пометка вымышленного примера сохраняется; пример не становится вашим опытом. Импорт не публикует данные.

Бесплатная версия описывает один кейс. Она не включает библиотеку кейсов, изображения, темы, сайт с профилем или планы для нескольких вакансий. Эти задачи выполняют отдельные Portfolio Case Kit и Interview Proof Kit. Выбор файла и продолжение работы остаются под вашим контролем.

Как опубликовать HTML

Редактор не размещает страницу и не выдаёт публичную ссылку. Вы скачиваете готовый index.html, проверяете его локально и отдельно выбираете размещение.

  1. Скачайте HTML своего кейса и откройте файл в браузере. Проверьте результат, вымысел/факты, разрешение на публикацию и внешнюю ссылку.
  2. Для GitHub Pages создайте отдельный публичный репозиторий и загрузите готовый index.html в его корень. Не загружайте личный JSON или весь редактор.
  3. В Settings → Pages выберите Deploy from a branch, свою основную ветку и папку /(root). Сохраните настройку.
  4. Дождитесь завершения публикации и откройте адрес, показанный в Pages. Проверьте его без авторизации. Для обновления замените готовый index.html новым экспортом.

GitHub Pages доступен для публичных репозиториев на GitHub Free; доступность для приватных репозиториев зависит от плана. Страница Pages публична, даже если исходный репозиторий приватный. Меню и условия могут измениться — используйте официальную инструкцию GitHub.

Use and privacy

Choose one task from your own experience: work, a personal project or a course project. Describe the problem, your responsibility, your decision and alternative, observed result, evidence and limits.

The blank worksheet contains no achievements. A fictional example opens separately and never replaces your draft. Its exports always keep a fictional-content notice.

  • The editor stores one draft in this browser’s localStorage. It sends no entered text, links or files to an API, includes no analytics and requires no account.
  • Loading the editor and following links use the network. Destination sites and hosting services may keep technical logs. Your evidence link is not opened automatically.
  • Autosave may be unavailable in private browsing or restricted storage; a warning appears. Download JSON before closing the page. Clearing browser data removes the local draft.
  • JSON is a private one-case backup. Only this free editor’s format is accepted, up to 256 KiB. Replacing a draft downloads the previous one first and keeps one local rescue copy when browser storage is available.
  • A corrupted saved draft is protected from overwrite. Download the original, restore a valid backup, or confirm a new blank case study.
  • RU/EN changes labels and export language. Your text is not translated automatically.

Review before sharing

Filled fields do not establish truthful experience. State your personal contribution; do not claim the entire team’s work. Remove secrets, invented percentages, client identities, private addresses and other people’s personal data. If evidence is private, explain the available verification boundary instead of publishing it without permission.

The optional evidence link accepts HTTPS without credentials. The editor checks format, not existence or the recipient’s access. Check it yourself while signed out. The optional Kornilov Tools credit link is off by default.

Your files

  • technical-case.md: Markdown with your case study, without the editor.
  • index.html: standalone HTML with embedded styles, no scripts or remote assets. It works locally offline. An external link opens only when clicked.
  • my-case-backup.json: a private editable draft. Keep it separate from the public page.
  • one-case-career-library.json: a separate experience file for your chosen import into Portfolio Case Kit or Interview Proof Kit. It preserves the case fields, stable ID and fictional flag without the editor’s private preferences.

Continue in Portfolio or Interview

  1. Fill the required fields and choose “Download experience for Portfolio / Interview”. This file is different from the editor backup.
  2. Open your Portfolio Case Kit or Interview Proof Kit 1.1 editor. Choose “Add experience” and select one-case-career-library.json. If the button is absent, update to an editor version that supports the experience library.
  3. Review the imported case. Importing it again updates the same stable ID rather than creating a copy. A fictional example keeps its fictional flag and does not become your experience. Importing does not publish your data.

The free tool covers one case. Several cases, images, themes, a profile website and preparation for multiple vacancies belong to the separate Portfolio Case Kit and Interview Proof Kit. You choose the file and control the next step.

Publish the HTML separately

The editor does not host your page or create a public link. Download your own index.html, review it locally and choose hosting separately.

  1. Open the exported HTML in your browser. Check facts, publication permission and evidence-link access.
  2. For GitHub Pages, create a separate public repository and upload only the exported index.html at its root. Do not upload the private JSON or the editor.
  3. Open Settings → Pages → Deploy from a branch, choose your main branch and /(root), then save.
  4. Wait for deployment and use the address shown in Pages. Check it while signed out. Update by replacing index.html with a fresh export.

GitHub Pages is available for public repositories on GitHub Free; private-repository availability depends on the plan. A Pages site is public even if the source repository is private. Refer to GitHub’s official instructions for current menus and conditions.
